What this adds
---------------
Portfolio Builder now has a "Universe" choice at the top: "Model ETFs" (the
existing 17-fund universe, unchanged) or "Investelity Top Picks" (build a
portfolio from investelity's own top-ranked individual stocks/funds, per
country and trailing period). Rebalancing then compares against whichever
universe a client's saved target used, same as always.

Important bug fix in core/optimization/engine.py
--------------------------------------------------
While wiring this up, portfolios built from investelity data were coming out
with nonsense numbers -- Sharpe ratios in the thousands to quadrillions, and
an empty efficient-frontier chart for small countries. The cause: the
optimizer (PyPortfolioOpt) annualizes returns/risk assuming DAILY prices by
default (252 trading days/year), which is correct for the existing ETF
universe (daily yfinance data) but was silently wrong for investelity's
data, which is priced MONTHLY. A real 5% monthly return was getting
compounded as if it were a 5% *daily* return happening 252 times a year.

The fix makes the optimizer infer the correct annualization frequency from
the actual spacing between price dates, so it's automatically right for
daily data (252), monthly data (12), or anything else -- no per-caller
guesswork. Verified this doesn't change any ETF-universe numbers at all
(confirmed frequency still infers to 252 there) and fixes every previously-
broken investelity case tested (US, Venezuela, a US-funds bucket, Germany).

Even after that fix, Sharpe ratios for the Investelity Top Picks universe
still run unusually high (think ~5-30, not the old quadrillions) -- that's
a real, expected side effect of building a portfolio out of tickers that
were *already* selected by investelity's own trailing-Sharpe ranking
(selection bias), not a bug. The page now shows a prominent warning banner
explaining this whenever that universe is selected, plus an inline
"unusually high -- treat as an unstable estimate" flag on any individual
metric above 5.0, so a consultant looking at these numbers isn't misled
into treating them as normal, trustworthy forecasts.
